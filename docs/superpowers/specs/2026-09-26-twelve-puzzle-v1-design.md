# 열두 퍼즐 1차 완성 설계

작성일: 2026-09-26  
대상 저장소: `goinggame`  
제품명: **열두 퍼즐**

## 1. 목적과 성공 기준

기존 세로형 동물 정렬 퍼즐을 광고와 서버 없이도 하나의 완성된 모바일 게임으로 다듬는다. 플레이어는 고양이·병아리와 열두 수호동물을 한 종류씩 세로 열에 모으고, 순차적으로 열리는 20개 단계를 완료한다. 후반 난이도는 보드를 무한히 키우는 방식이 아니라 숨김 깊이, 빈 열 수, 배치 혼합도와 공개된 특수 규칙으로 높인다.

1차 완성의 성공 기준은 다음과 같다.

- 20개 단계가 순서대로 해제되고 모든 단계가 규칙을 지키는 검증된 정답 경로를 가진다.
- 기본 이동, 이동 제한, 타임어택, 아이템, 게임오버, 저장, 로컬 순위가 함께 동작한다.
- 14종 동물, 특수 타일, 앱 아이콘과 메뉴 전체가 포근한 16비트 픽셀 스타일로 통일된다.
- 320px 폭의 웹 화면부터 아이폰까지 핵심 버튼과 보드가 잘리지 않는다.
- 자동검사, 웹 빌드, iOS 동기화와 서명된 개발 빌드가 통과하고 아이폰에 재설치된다.
- 실제 아이폰에서 초반·중반·최종 구간의 터치, 드래그, 스크롤과 플레이 시간이 수동 검증된다.

## 2. 범위와 제외 범위

### 포함

- `열두 수호대`에서 `열두 퍼즐`로 사용자 노출 이름 변경
- 5단계에서 20단계로 확장
- 수호 목표, 표식 열, 봉인 열과 후반 조합 단계
- 새 저장 체계, 순차 해제, 현재 판 저장, 로컬 순위
- 포근한 16비트 픽셀 아트와 전체 픽셀 UI
- 기존 이동/타이머/아이템/게임오버/접근성 동작 유지
- 웹 및 iOS 개발 빌드 검증

### 제외

- 온라인 전체 순위, 로그인, 계정 동기화, 서버 백엔드
- 실제 광고 송출, UMP/ATT 운영 흐름, 인앱 결제
- App Store와 Google Play의 실제 제출 및 유료 Apple 멤버십 결제
- 사용자를 속이는 난수 방해, 예고 없는 보드 섞기, 검증되지 않은 보드

광고 SDK 코드는 향후 작업을 위해 남길 수 있지만, 광고가 비활성화된 1차 완성본에서는 광고 보급 버튼과 광고 개인정보 설정을 사용자에게 노출하지 않는다. 기본 아이템과 재시작만으로 모든 단계를 플레이할 수 있어야 한다.

## 3. 브랜드와 시각 디자인

### 이름

- 사용자 노출 앱 이름: `열두 퍼즐`
- iOS/Android 표시 이름, 웹 제목, 헤더, 문서와 개인정보처리방침 초안을 모두 변경한다.
- 번들 식별자 `com.onewaycompany.twelveguardians`는 기존 네이티브 프로젝트와 설치 호환을 위해 유지한다.

### 픽셀 아트 방향

- 선택안: **포근한 16비트**
- 색상: 아이보리, 크림, 살구, 청자색, 잎사귀색
- 외곽선: 짙은 갈색 또는 짙은 청록색의 1~2픽셀 선
- 중국식 문양, 한자, 붉은색·금색 궁전 장식은 사용하지 않는다.
- 14종 동물은 얼굴 중심의 같은 비율과 광원으로 제작하며 작은 화면에서도 실루엣과 귀·뿔·무늬가 구분되어야 한다.
- 동물용 4×4 아틀라스, 특수 타일용 별도 아틀라스, 픽셀 앱 아이콘을 만든다.
- 이동은 짧은 픽셀 점프, 착지는 1~2단계 눌림, 숨김은 카드 뒤집기, 완성은 제한된 반짝임으로 표현한다.
- `prefers-reduced-motion`에서는 이동과 반짝임을 즉시 상태 변경으로 대체한다.

### 글꼴과 UI

- 본문과 메뉴는 자체 호스팅 `Galmuri11`, 제목과 중요한 수치는 `Galmuri11 Bold`를 사용한다.
- 글꼴과 SIL Open Font License 1.1 전문을 앱에 포함하고 CDN 요청은 사용하지 않는다.
- 버튼, 단계 카드, 모달, 진행 막대는 각진 픽셀 테두리와 계단식 그림자를 사용한다.
- 픽셀 글꼴의 작은 크기 문제를 피하기 위해 본문 최소 크기와 줄 간격을 넉넉하게 두고, 축소된 보조 문구도 아이폰에서 읽을 수 있게 한다.
- 글꼴 또는 이미지가 로드되지 않아도 시스템 글꼴, 텍스트 이름과 접근성 라벨로 게임을 진행할 수 있어야 한다.

## 4. 핵심 규칙

- 각 열은 아래에서 위 순서로 동물을 보관한다.
- 플레이어는 공개된 맨 위 동물 한 마리를 공간이 남은 다른 열로 옮긴다.
- 목적지가 비어 있거나 다른 동물이 있어도 이동할 수 있다.
- 자기 열, 가득 찬 열, 숨겨진 맨 위 타일, 특수 규칙이 거부하는 목적지에는 이동할 수 없다.
- 비어 있지 않은 모든 열이 용량만큼 같은 동물로 채워지고 숨김이 남지 않으면 승리한다.
- 여정은 이동 제한 또는 타임어택 중 하나를 사용하고, 연습은 제한과 게임오버가 없다.
- 선택 취소, 잘못된 드롭과 차단된 이동은 이동 수를 사용하지 않는다.
- 마지막 허용 이동으로 완성하면 게임오버보다 승리가 우선한다.
- 기본 아이템은 되돌리기 3개, 한 열 공개 2개, 보조 칸 1개다. 광고 없이 다시 시작할 수 있다.

## 6. 특수 규칙의 정확한 의미

특수 규칙은 시작 화면과 보드에 항상 표시하며 진행 중 예고 없이 바뀌지 않는다.

### 수호 목표

- 한 동물 종류를 이번 단계의 목표로 표시한다.
- 목표가 완성되기 전에는 다른 종류를 완성시키는 마지막 타일 이동을 거부한다.
- 생성기가 가진 정답 경로에서 가장 먼저 완성되는 종류를 목표로 선택해 검증된 경로를 유지한다.
- 목표가 한 번 완성되면 달성 상태를 저장하며, 이후 목표 열이 다시 흐트러져도 다른 종류 완성 제한은 되살아나지 않는다.

### 표식 열

- 1개 또는 2개의 열에 받을 수 있는 동물 종류를 시작부터 표시한다.
- 표식 열에서 동물을 꺼내는 것은 허용하지만, 그 열로 넣는 동물은 표시된 종류만 허용한다.
- 표식 열에 시작부터 섞여 있던 다른 동물은 합법적인 시작 상태이며 밖으로 이동할 수 있다.
- 생성기는 정답 경로의 모든 유입 이동이 표식과 일치하는 열만 선택한다.

### 봉인 열

- 한 열은 지정된 `해제 동물`이 최초로 완성될 때까지 출발지와 목적지로 사용할 수 없다. 13~16단계의 해제 동물은 수호 목표 규칙을 함께 활성화하지 않는다.
- 봉인된 열의 내용은 보이되 흐리게 표시하고 자물쇠와 해제 조건을 함께 보여준다.
- 생성기는 해제 동물 달성 전 정답 경로에서 사용하지 않는 열만 봉인 대상으로 선택한다.
- 해제 상태는 현재 판 저장에 포함하고 다시 잠기지 않는다.

### 조합 규칙

- 17~19단계는 두 규칙, 20단계는 세 규칙을 함께 사용한다.
- 수호 목표와 봉인 열이 함께 등장하면 같은 동물 종류를 목표와 해제 조건으로 사용한다.
- 하나의 이동은 기본 규칙과 활성 특수 규칙을 모두 만족해야 한다.
- 조합 단계도 단일 규칙과 같은 정답 경로 재생 검증을 통과해야만 제공한다.

## 7. 생성과 난이도

- 완성된 보드에서 합법적인 역이동으로 섞고, 앞으로 되돌릴 수 있는 정답 경로를 함께 만든다.
- 여러 후보 중 동물 종류 전환 수와 빈 열 의존도가 높은 배치를 선택한다.
- 특수 규칙은 기본 후보와 정답 경로를 분석해 호환되는 목표와 열을 고른다.
- 호환되는 특수 규칙 구성을 찾지 못하면 후보를 버린다. 시드당 최대 40개 후보를 검사하고, 실패하면 시드를 최대 16회 증가시켜 다시 생성한다. 모두 실패하면 검증되지 않은 보드를 보여주지 않고 생성 실패 안내와 `다른 배치 만들기` 버튼을 제공한다.
- 이동 제한은 규칙을 포함한 반복 제거 정답 경로 길이에 `1.25`를 곱해 올림한 뒤 8을 더하고, 최소 24수로 계산한다. 최적 풀이 수라고 표시하지 않는다.
- 1~20단계 타임어택은 각각 `90, 110, 130, 150, 180, 210, 240, 270, 300, 330, 360, 390, 420, 450, 480, 510, 540, 570, 600, 660초`로 시작한다. 실제 사용자 기록을 근거로 후속 버전에서 조정한다.
- 연습 모드는 같은 보드 크기와 특수 규칙을 사용하지만 숨김, 시간, 이동 제한과 게임오버를 제거한다.

## 8. 상태와 저장

공개 전 게임이므로 예전 5단계 저장을 새 구조로 변환하지 않는다. 기존 키는 삭제하지 않고 새 버전에서 무시한다.

새 저장은 다음을 분리해 보관한다.

- 튜토리얼 완료 여부
- 연속으로 완료한 단계와 현재 해제 단계
- 현재 판의 시드, 단계, 모드, 도전 방식, 보드, 특수 규칙 진행, 이동 수, 아이템, 타이머
- 로컬 닉네임과 최근 클리어 기록

진행 중 판은 이동과 특수 규칙 변화 직후 저장한다. 저장 공간 부족이나 접근 거부가 발생하면 메모리 상태로 계속 플레이하고 사용자에게 해당 실행에서만 유지된다는 경고를 보여준다. 손상되거나 버전이 맞지 않는 저장은 임의 수리하지 않고 새 판으로 시작한다.

## 9. 로컬 순위

- 여정 모드에서 정상 완료한 판만 등록한다.
- 단계, 시드, 이동 제한/타임어택, 아이템 사용 여부를 구분한다.
- 이동 제한은 적은 이동 수, 타임어택은 짧은 실제 플레이 시간을 우선한다.
- 일시정지, 도움말, 애니메이션과 앱 백그라운드 시간은 타임어택 기록에서 제외한다.
- 동일 시도 ID는 한 번만 기록하고 최근 200개를 보관한다.
- 연습, 실패, 손상된 저장, 규칙 버전이 다른 기록은 현재 순위에 넣지 않는다.
- 온라인 전체 순위가 아니라 이 기기 기록임을 화면에 명확히 표시한다.

## 10. 코드 구조

- 단계 데이터: 크기, 동물, 숨김, 빈 열, 규칙 조합과 시간 설정
- 기본 엔진: 상태 복제, 맨 위 동물, 기본 이동, 승리, 합법 이동 열거
- 규칙 엔진: 수호 목표, 표식 열, 봉인 열의 이동 판정과 진행 상태
- 생성기: 역이동 보드, 정답 경로, 규칙 호환 분석, 후보 선택
- 세션: 제한, 타이머, 아이템, 게임오버와 부활 없는 광고 비활성 흐름
- 저장/진행/순위: 새 버전 키와 검증 함수
- 표시 계층: 보드, 특수 규칙 안내, 픽셀 애니메이션, 튜토리얼, 순위

규칙 판정은 DOM과 분리된 순수 함수로 유지한다. UI는 엔진이 반환한 이동 가능 여부와 규칙 상태를 표시하며 자체적으로 합법성을 결정하지 않는다.

## 11. 오류 처리와 접근성

- 생성 실패: 다음 후보 또는 다음 시드로 재시도하고 검증되지 않은 보드는 노출하지 않는다.
- 저장 실패: 메모리 플레이를 유지하고 영구 저장 실패를 알린다.
- 이미지/폰트 실패: 시스템 글꼴, 동물 이름, 접근성 라벨로 조작 가능하게 한다.
- 드래그 취소, 앱 전환, 두 번째 포인터와 잘못된 드롭은 상태를 바꾸지 않는다.
- 터치 외에 출발·도착 두 번 누르기와 키보드 조작을 유지한다.
- 특수 열은 색만으로 구분하지 않고 아이콘, 패턴, 이름과 접근성 설명을 함께 사용한다.
- 모달과 일시정지 화면은 초점을 가두고 닫은 뒤 적절한 조작 요소로 초점을 돌린다.

## 13. 완료 이후

1차 완성 및 실제 플레이 밸런싱 후에만 온라인 순위, 실제 광고와 스토어 제출을 별도 프로젝트로 진행한다. 온라인 순위를 추가할 때는 서버 측 규칙 버전, 시드, 이동 기록 검증과 닉네임 관리가 필요하다. 광고를 추가할 때는 대상 연령, 개인정보 고지, UMP/ATT와 실기기 광고 테스트를 먼저 확정한다.

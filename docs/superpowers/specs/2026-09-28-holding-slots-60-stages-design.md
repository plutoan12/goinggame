# 열두 퍼즐 임시 보관칸·60단계 확장 설계

작성일: 2026-09-28
대상 저장소: `goinggame`
제품명: **열두 퍼즐**

## 1. 목적

현재 20단계 세로형 동물 정렬 퍼즐을 60단계로 확장하고, 메인 세로줄과 별개의 1장짜리 자유 보관칸을 추가한다. 초반에는 보관칸이 넉넉하지만 후반으로 갈수록 수가 줄어들고, 세로 길이와 물음표 비율이 함께 증가한다. 난이도는 단순 반복이나 불공정한 난수가 아니라 공간 관리, 기억, 이동 순서와 제한 자원 판단에서 나온다.

성공 기준은 다음과 같다.

- 60개 단계가 순차적으로 해제된다.
- 보관칸은 메인 보드와 자유롭게 한 장씩 주고받을 수 있다.
- 물음표는 위 타일이 빠져 맨 위가 되는 즉시 자동 공개된다.
- 모든 생성 보드는 정답 경로 검증을 통과한다.
- 보관칸 이동이 되돌리기, 저장, 게임오버, 순위와 일관되게 작동한다.
- 일반 단계는 5~12분, 구간 보스는 최대 15~20분 안에 끝나는 분량을 목표로 한다.
- 14~16칸 높이의 특별 보드도 아이폰에서 타일을 지나치게 축소하지 않고 조작할 수 있다.

## 2. 선택한 구현 접근

기존 엔진을 유지하면서 보관칸을 별도 상태로 추가하는 **현재 엔진 확장형**을 사용한다.

- 메인 세로줄의 혼합 적재, 특수 규칙, 정답 경로 생성 구조를 유지한다.
- 보관칸은 메인 세로줄로 취급하지 않고 별도 배열로 관리한다.
- 60단계는 고정 시드 생성기를 사용하되 10·20·30·40·50·60단계를 별도로 검증하고 보정한다.
- 전면 엔진 재작성과 60개 단계 완전 수동 배치는 범위에서 제외한다.

이 접근은 기존 테스트와 네이티브 프로젝트를 최대한 보존하면서 새 규칙을 명확하게 격리한다.

## 3. 자유 보관칸 규칙

### 기본 동작

- 보관칸 한 칸에는 공개된 동물 한 마리만 들어간다.
- 메인 세로줄의 공개된 맨 위 동물을 빈 보관칸으로 이동할 수 있다.
- 보관한 동물은 공간이 남고 특수 규칙이 허용하는 어떤 메인 세로줄로도 다시 이동할 수 있다.
- 보관칸끼리는 이동할 수 없다.
- 보관칸에 넣기와 메인 세로줄로 꺼내기는 각각 이동 1회다.
- 잘못된 선택, 가득 찬 목적지와 차단된 이동은 상태와 이동 횟수를 바꾸지 않는다.
- 보관칸이 모두 찼다는 사실만으로는 게임오버가 아니다.

### 물음표 공개

- 메인 세로줄에서 동물이 빠진 직후 새 맨 위 타일이 물음표라면 즉시 공개한다.
- 메인 세로줄끼리의 이동과 메인 세로줄에서 보관칸으로 보내는 이동에 같은 공개 규칙을 적용한다.
- 보관칸에는 숨겨진 타일을 넣을 수 없고 보관칸 안의 동물은 항상 공개 상태다.
- 자동 공개 자체는 이동 횟수를 추가로 사용하지 않는다.

### 특수 규칙과의 관계

- 봉인된 세로줄에서는 보관칸으로 꺼낼 수 없고, 보관칸에서도 봉인된 세로줄로 넣을 수 없다.
- 표식 세로줄로 되돌릴 때는 보관 동물이 지정 종류와 일치해야 한다.
- 보관칸에서 메인 세로줄로 옮겨 한 종류를 완성한 경우에도 수호 목표와 봉인 해제 판정을 수행한다.
- 수호 목표가 다른 종류의 완성을 막는 상황에서는 보관칸에서 해당 완성을 만드는 이동도 거부한다.

### 승리와 게임오버

- 비어 있지 않은 모든 메인 세로줄이 용량만큼 같은 동물로 채워지고, 숨김 타일이 없으며, 모든 보관칸이 비어 있어야 승리한다.
- 승리 판정을 시간·이동 제한 소진 판정보다 먼저 수행해 마지막 허용 이동으로 완성할 수 있다.
- 여정 모드에서는 제한 시간 종료, 이동 횟수 소진 또는 합법적인 이동이 전혀 없으면 게임오버다.
- 합법 이동 탐색은 메인 세로줄 간 이동, 메인 세로줄에서 보관칸으로 이동, 보관칸에서 메인 세로줄로 이동을 모두 포함한다.
- 교착 상태여도 사용하지 않은 보관칸 추가 또는 되돌리기 아이템으로 복구할 수 있으면 아이템 선택 화면을 먼저 제공한다.
- 연습 모드는 시간·이동 제한과 교착 게임오버를 적용하지 않는다.

## 4. 상태와 이동 모델

게임 상태는 개념적으로 다음 정보를 포함한다.

```text
state
├─ capacity
├─ tubes[]
├─ hidden[][]
└─ holding[]       // 동물 ID 또는 빈 값
```

단계 설정에는 기본 보관칸 수를 뜻하는 `holdingSlots`를 추가한다. 보관칸 추가 아이템을 사용하면 현재 판의 `holding` 배열 끝에 빈 칸 한 개를 더하며, 기본 수와 아이템 추가 여부는 별도로 검증할 수 있어야 한다.

이동 기록은 출발지와 목적지를 숫자만으로 표현하지 않고 위치 종류를 포함한다.

```text
location = { kind: "tube" | "holding", index: number }
move = { from: location, to: location }
```

DOM은 이동 가능 여부를 직접 판단하지 않는다. 기본 엔진과 규칙 엔진이 이동 가능 여부와 적용 결과를 반환하고, 화면은 그 결과만 표현한다.

## 5. 60단계 난이도 곡선

단계는 10개씩 여섯 구간으로 표시한다. 구간 이름과 배경은 들길, 숲, 바람, 별빛, 달빛처럼 한국어 자연 소재를 사용하고 한자, 중국식 문양, 붉은색·금색 궁전 장식을 사용하지 않는다.

| 단계 | 세로 길이 | 동물 종류 | 목표 물음표 비율 | 기본 보관칸 | 목표 시간 |
|---|---:|---:|---:|---:|---:|
| 1~10 | 4~6칸 | 4~8종 | 10~35% | 3개 | 2~4분 |
| 11~20 | 6~8칸 | 8~11종 | 35~55% | 3개에서 2개 | 4~7분 |
| 21~30 | 8~10칸 | 10~12종, 30단계 14종 | 55~70% | 2개 | 5~9분 |
| 31~40 | 9~12칸 | 10~12종, 40단계 14종 | 65~82% | 2개에서 1개 | 7~12분 |
| 41~50 | 10~14칸 | 10~12종, 50단계 14종 | 75~90% | 1개 | 8~15분 |
| 51~59 | 12~14칸 | 10~12종 | 85~92% | 1개 | 10~15분 |
| 60 | 16칸 | 14종 | 최대 93.75% | 0개 | 15~20분 |

### 단계 생성 원칙

- 각 세로줄의 현재 맨 위는 공개하고, 설정된 숨김 깊이만큼 아래 타일을 물음표로 만든다.
- 16칸 세로줄에서 맨 위 한 장만 공개하면 자연스러운 최대 숨김 비율은 `15/16`, 즉 93.75%다.
- 1단계부터 물음표를 사용하되 초반에는 일부만 숨겨 규칙을 학습하게 한다.
- 세로 길이, 동물 수, 빈 메인 세로줄 수, 숨김 깊이, 특수 규칙, 시간·이동 제한과 보관칸 수를 함께 조절한다.
- 고양이·병아리와 열두 수호동물은 게임 전체에 모두 등장하지만, 일반 후반 단계에서는 10~12종을 순환해 한 판의 길이를 제한한다.
- 14종 전체와 16칸 세로줄은 반복 사용하지 않고 구간 보스, 특히 60단계에 집중한다.
- 각 10단계 구간은 `상승 3단계 → 휴식 1단계 → 상승 3단계 → 휴식 1단계 → 예비 시험 → 보스`의 파형을 사용한다. 휴식 단계도 이전 구간보다 쉽지는 않지만 직전 단계보다 짧고 보관칸이나 빈 줄이 하나 더 넉넉하다.
- 물음표 90% 이상은 일부 후반 단계와 60단계에만 사용한다.
- 기본 보관칸 0개는 60단계에만 사용한다.
- 마지막 단계도 최소 한 개의 메인 빈 세로줄을 유지해 보관칸 아이템 없이도 검증된 정답 경로가 존재하게 한다.
- 동일 단계와 시드는 모든 플레이어에게 같은 판을 제공할 수 있도록 결정론적으로 생성한다.
- 생성기가 보유한 해답은 보관칸을 반드시 사용하지 않아도 되는 안전 경로다. 보관칸은 플레이어가 다른 해법을 만들 수 있는 전략 공간으로 작동한다.

### 중요 단계 검증

- 10·20·30·40·50·60단계는 구간의 최종 시험 역할을 한다.
- 중요 단계는 자동 생성 후 정답 길이, 혼합도, 초반 선택지, 빈 세로줄 의존도와 물음표 비율을 별도로 검사한다.
- 지나치게 단순하거나 시작 직후 사실상 한 경로만 강요하는 후보는 버린다.
- 생성된 반복 제거 해답 길이와 실기기 플레이 표본을 함께 사용해 일반 단계는 5~12분, 보스 단계는 최대 15~20분을 목표로 조정한다.
- 목표 시간을 크게 초과하는 후보는 물음표를 줄이는 대신 동물 종류, 세로 길이 또는 혼합도를 낮춰 다시 생성한다.
- 생성 실패 시 검증되지 않은 판을 보여주지 않고 다른 후보와 시드를 사용한다.

## 6. 아이템과 광고 준비

기존의 메인 빈 세로줄 하나를 추가하는 `보조 칸` 아이템은 제거하고 **임시 보관칸 +1** 아이템으로 교체한다.

- 한 판에 한 번만 사용할 수 있다.
- 기본 보관칸 수와 관계없이 최대 한 칸만 추가한다. 기본 보관칸이 0개인 최종 구간에서도 사용할 수 있다.
- 추가 칸은 해당 판에서만 유지한다.
- 사용 전의 되돌리기 기록은 기존 정책대로 초기화해 아이템을 되돌려 환급할 수 없게 한다.
- 되돌리기 3개와 한 세로줄 전체 공개 2개는 유지한다.
- 광고 기능이 비활성화된 현재 릴리스에서는 기본 아이템만 제공한다.
- 향후 보상형 광고를 켤 때는 임시 보관칸 +1을 보상 선택지로 연결할 수 있다.
- 임시 보관칸 추가, 전체 공개, 되돌리기와 광고 보상을 사용한 완료 기록은 `도움받음`으로 분류한다.
- 시간 또는 이동 횟수가 이미 소진된 경우 임시 보관칸을 열어도 제한을 복구하지 않는다.

## 7. 화면과 조작

- 상태 표시줄 아래, 메인 보드 위에 보관칸 영역을 둔다.
- 보드를 가로·세로로 스크롤해도 보관칸은 화면에 고정한다.
- 기본 보관칸이 0개이고 추가 아이템도 사용하지 않은 단계에는 `보관칸 없음` 배지를 표시한다.
- 메인 동물을 보관칸으로 끌어 놓거나 출발 동물과 빈 보관칸을 차례로 눌러 이동할 수 있다.
- 보관칸의 동물도 메인 세로줄로 드래그하거나 출발·도착을 차례로 눌러 복귀할 수 있다.
- 선택한 동물과 합법적인 목적지는 색 이외의 픽셀 테두리와 패턴으로 강조한다.
- 불가능한 이동은 짧은 흔들림과 접근성 안내를 제공하되 이동 횟수를 차감하지 않는다.
- 이동이 끝난 뒤 새 맨 위 물음표를 짧은 픽셀 뒤집기 효과로 공개한다.
- 임시 보관칸 추가 아이템을 쓰면 빈 칸이 픽셀 조각으로 조립되는 짧은 연출을 사용한다.
- `prefers-reduced-motion`에서는 이동, 흔들림, 뒤집기와 조립 연출을 즉시 상태 변경으로 대체한다.
- 후반의 14~16칸 세로줄은 타일을 과도하게 축소하지 않고 보드 내부 세로 스크롤을 사용한다.
- 첫 단계 튜토리얼은 메인 세로줄에서 보관칸으로 보내고 다시 메인 세로줄로 꺼내는 과정을 직접 수행하게 한다.

## 8. 진행과 저장

- 1단계를 완료해야 2단계가 열리는 순차 해금을 60단계까지 유지한다.
- 기존 1~20단계 번호는 유지하고 21~60단계를 뒤에 추가한다.
- 저장 규칙 버전을 올리고 현재 진행 중인 구버전 판은 새 규칙에서 재개하지 않는다.
- 유효한 기존 튜토리얼 완료와 최고 해금 단계는 가능한 범위에서 보존한다.
- 구버전 순위 기록은 규칙 버전이 달라 새 순위표에 섞지 않는다.
- 현재 판 저장에는 단계, 시드, 모드, 제한 방식, 메인 보드, 물음표, 보관칸 내용과 개수, 보관칸 아이템 여부, 특수 규칙 진행, 이동 수, 아이템, 타이머와 감사 로그를 포함한다.
- 보관칸을 포함한 모든 정상 이동 직후 저장한다.
- 앱 종료, 강제 종료와 백그라운드 전환 후 같은 상태에서 계속할 수 있어야 한다.
- 손상되거나 규칙 버전이 맞지 않는 현재 판은 임의로 수리하지 않고 새 판으로 안내한다.

## 9. 로컬 순위

- 이번 범위는 서버가 필요 없는 기기 내 순위까지 포함한다.
- 단계, 보드 시드, 이동 제한/타임어택과 규칙 버전이 같은 기록끼리만 비교한다.
- 정상 기록과 `도움받음` 기록을 구분해 표시한다.
- 이동 제한은 적은 이동 수를, 타임어택은 짧은 실제 플레이 시간을 우선한다.
- 일시정지, 도움말, 애니메이션과 앱 백그라운드 시간은 타임어택 기록에서 제외한다.
- 연습, 실패, 손상 저장과 검증되지 않은 감사 로그는 순위에 등록하지 않는다.
- 온라인 통합 순위는 후속 버전에서 서버 측 시드·규칙·이동 로그 검증과 함께 추가할 수 있도록 기록 구조에 규칙 버전을 남긴다.

## 10. 오류 처리

- 보관칸 이동 중 드래그 취소, 앱 전환, 두 번째 포인터와 잘못된 드롭은 상태를 변경하지 않는다.
- 저장 실패 시 현재 메모리 플레이를 유지하고 해당 실행에서만 유지된다는 안내를 표시한다.
- 생성 실패 시 검증되지 않은 판을 시작하지 않고 다른 배치 생성 동작을 제공한다.
- 이미지나 글꼴 로드 실패 시 시스템 글꼴, 동물 이름과 접근성 라벨로 계속 조작할 수 있어야 한다.
- 보관칸 추가 아이템을 사용한 상태에서 저장 공간이나 감사 로그 검증이 어긋나면 순위 등록을 거부한다.

## 11. 검증 계획

### 엔진과 생성기

- 메인 세로줄에서 빈 보관칸으로 이동
- 보관칸에서 합법적인 메인 세로줄로 이동
- 가득 찬 보관칸, 보관칸 간 이동과 숨겨진 타일 이동 거부
- 보관 이동 직후 새 맨 위 물음표 자동 공개
- 봉인 열, 표식 열과 수호 목표가 보관 이동에도 적용되는지 검증
- 보관칸이 남아 있는 상태에서는 승리하지 않는지 검증
- 메인 이동과 보관 이동을 모두 포함한 교착 판정
- 되돌리기로 보관칸 내용, 공개 상태, 이동 수와 특수 규칙 진행 복원
- 60단계의 설정 범위, 순차 해금과 단계 그룹 표시
- 두 모드와 다수 시드에서 60단계 정답 경로 전체 재생
- 중요 단계의 목표 물음표 비율과 난이도 휴리스틱 검증

### 저장과 순위

- 보관칸 내용과 아이템 추가 칸의 저장·복원
- 구버전 현재 판 무효화와 해금 진행 보존
- 감사 로그에서 메인↔보관 이동 재생과 변조 거부
- 규칙 버전, 단계, 시드와 제한 방식별 순위 분리
- 보관칸 추가, 공개와 되돌리기 사용 기록의 `도움받음` 분류

### 화면과 네이티브

- 320px, 390px와 실제 아이폰에서 보관칸의 고정 위치 확인
- 탭, 드래그, 취소, 자동 스크롤과 접근성 조작 확인
- 4·8·12·16칸 높이에서 타일 크기와 세로 스크롤 확인
- 물음표 자동 공개와 동작 줄이기 설정 확인
- 1·10·20·30·40·50·60단계의 실제 플레이 확인
- 웹 빌드, Capacitor 동기화, iOS 시뮬레이터와 Android 빌드 확인

## 12. 제외 범위와 후속 작업

이번 확장에 실제 광고 송출, 온라인 통합 순위, 로그인, 계정 동기화, 인앱 결제와 스토어 제출은 포함하지 않는다. 광고 코드는 기본 비활성 상태를 유지한다. 게임 밸런스와 실기기 조작을 먼저 완성한 뒤 대상 연령, 개인정보처리방침 공개 URL, 광고 동의 흐름과 스토어 운영 계정을 확정해 별도 단계로 진행한다.

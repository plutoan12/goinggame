# 열두 수호대 · 십이지신 정렬 퍼즐

[참고 영상](https://www.youtube.com/watch?v=QARuInPBK_g)의 세로 정렬 방식을 바탕으로 만든 한국어 웹 게임입니다. 쥐·소·호랑이·토끼·용·뱀·말·양·원숭이·닭·개·돼지의 열두 수호동물을 모읍니다. 한글 중심, 아이보리와 청자색의 담백한 화면으로 재해석했습니다. 특정 전통 양식의 역사적 복원이나 원작 공식 버전은 아닙니다.

## 실행

웹 미리보기는 설치·빌드·서버 API 없이 정적 파일만 사용합니다. iOS·Android 설치형 앱 프로젝트도 포함되어 있습니다. [모바일 앱 준비 안내](./MOBILE.md)를 참고하세요.

```sh
python3 -m http.server 4173
```

http://localhost:4173 에서 플레이합니다. `file://`로 직접 열면 JS 모듈을 로드할 수 없으므로 HTTP 서버를 사용하세요.

## 적용한 규칙

- 첫걸음 튜토리얼: 고양이·병아리 4열 × 3칸의 별도 연습판에서 세 번의 안내 이동을 익힙니다. 시간·횟수 제한과 아이템 없이 드래그·두 번 터치·키보드로 진행합니다. 완료 전에는 실행 시 안내를 열고(기존 승리/실패 창 우선), 완료 여부만 별도 저장합니다. 도움말 → ‘작은 판으로 이동 연습’에서 다시 할 수 있습니다. 건너뛰어도 본게임은 이용 가능하며, 완료해도 산책 단계가 열리거나 순위에 기록되지 않습니다. 기존 본게임 저장·아이템·타이머·단계 기록은 유지합니다.

- 맨 위 동물 한 마리를 공간이 남은 다른 열로 옮깁니다. 다른 동물 위에도 쌓을 수 있고 가득 찬 열로는 이동할 수 없습니다. 아래의 물음표는 위 타일을 옮기면 공개됩니다. 같은 동물로 모든 비어 있지 않은 열을 가득 채우면 완성입니다.
- 모든 동물을 종류별로 한 칸 가득 모으면 완료됩니다. 같은 그림 3개를 모아도 사라지지 않습니다.
- 클리어 시 다음 단계로 진행하며, 난이도 버튼으로 직접 선택할 수도 있습니다.
- 연습 모드는 선택한 단계의 크기를 유지하되 모든 그림을 공개합니다.
- 여정에서 **이동 횟수 제한 / 타임어택**을 선택합니다. 두 제한을 동시에 걸지는 않습니다. 선택한 제한이 0이 되거나 가능한 이동이 0개이면 게임오버입니다. 마지막 허용 이동으로 완성하면 성공이 우선합니다. 연습에는 두 제한 모두 없습니다.
- 이동 제한은 `max(24, 반복을 제거한 복원 경로 길이 × 1.2 올림 + 6)`입니다. 생성기의 정답 경로에서 정확히 같은 상태로 돌아오는 순환을 지워 한도가 불필요하게 커지던 문제를 줄였습니다. 경로를 재생해 해법이 유효함을 검증하며, 최적 풀이를 구한 것은 아닙니다. 예: 시드 26491의 5단계는 경로 1,298수 → 169수, 한도 1,753수 → 209수입니다. 성공률 기반 밸런싱은 더 필요합니다.
- 타임어택은 1~5단계에 각각 **90 / 150 / 240 / 360 / 480초**입니다. 첫 유효 이동부터 시작합니다. 남은 시간/이동과 게이지는 스크롤해도 상단에 남으며 15초/10수 이하에서 경고색으로 바뀝니다.
- 타이머는 단조 시계로 경과 시간을 계산합니다. 광고·도움말·이동 애니메이션·수동 일시정지·앱/탭 전환 중 멈춥니다. 일시정지 시 보드도 가립니다. 새로고침/앱 복귀 시 계속하기를 눌러 재개합니다. 되돌리기는 시간을 복구하지 않습니다. 시간을 1초마다 저장하고 화면 이탈 때 정산합니다. 서버 타이머가 아니므로 로컬 저장 조작·강제 종료에 대한 치트 방지는 제공하지 않습니다.
- 매 판 되돌리기 3개, 한 열 공개 2개, 보조 칸 1개를 지급합니다. 되돌리기는 최근 100수 내에서 아이템만큼 사용하며 이동 횟수도 1회 돌려줍니다. 공개는 선택한 열 전체 물음표를 공개합니다. 공개·보조 칸 사용은 이전 되돌리기 기록을 초기화합니다.
- 게임오버 상태에서도 남은 되돌리기·보조 칸으로 구조하거나 광고 없이 다시 시작할 수 있습니다. 연습은 이동·되돌리기·공개 무제한이며 게임오버와 광고 보상이 없습니다.
- 선택형 광고 위치: 되돌리기 3개 충전 / 한 열 공개 2개 충전 / 게임오버 후 이동 모드 30수 또는 타임어택 60초 + 빈 칸 1개 이어하기. 각각 판당 1회, 완료 보상에만 지급합니다. 취소·실패는 차감하지 않습니다. 보상·수량·이어하기 여부를 저장합니다.
- **AdMob 네이티브 연결 코드는 추가됐지만 광고는 기본 꺼짐**입니다. 이용 연령 확정·동의 설정·실기기 검증 전에는 송출하지 않습니다. HTTP localhost 브라우저에서만 완료·취소·실패 시뮬레이션을 사용합니다. 네이티브 보상은 SDK 보상 이벤트와 닫힘 이벤트를 모두 확인한 후 지급합니다. 배너 및 전면 광고는 연결 위치 표시만 남아 있습니다. [모바일 준비 상태](./MOBILE.md) 및 [출시 체크리스트](./RELEASE.md)를 참고하세요.
- 결제·로그인·서버 랭킹은 없습니다. 진행 상황은 로컬에만 저장됩니다.

## 이 기기 순위

상단 **순위** 버튼에서 이름과 기록을 확인합니다. 여정 모드에서 클리어하면 자동으로 기록되며, 클리어 화면에 현재 순위와 같은 배치 재도전 버튼이 표시됩니다. **다른 기기·사용자의 온라인 순위는 아닙니다.** 가짜 플레이어나 예시 점수는 넣지 않습니다.

- 이동 제한: 적은 이동 수 순. 되돌린 이동은 기존 게임의 이동 카운트와 동일하게 제외됩니다.
- 타임어택: 짧은 실제 플레이 시간 순(0.1초 단위). 일시정지·광고·도움말·애니메이션은 제외하고, 부활로 얻은 시간도 포함해 소요 시간을 계산합니다.
- 단계 / 방식 / 같은 배치 / 아이템 사용 여부를 구분합니다. 서로 다른 배치를 포함하는 ‘단계 전체’는 참고용이라고 표시합니다. 동점은 1, 1, 3위처럼 공동 순위입니다.
- 되돌리기·공개·보조 칸·부활을 실제로 사용한 판은 ‘아이템 사용’ 그룹입니다. 아이템을 광고로 충전만 하고 사용하지 않은 판은 일반 그룹을 유지합니다. 연습·실패는 등록하지 않습니다.
- 최근에 등록된 클리어 기록 200개를 보관하고 선택한 조건의 상위 20개를 보여줍니다. 순위는 플레이어별 종합 점수가 아닌 **클리어 기록별 순위**입니다. 이름 변경은 다음 기록부터 적용됩니다.
- 시도 ID를 진행 저장에 함께 기록해 재접속·클리어 화면 재열기로 같은 기록이 중복 등록되지 않도록 합니다. 저장 오류 시 메모리에서만 유지하고 경고합니다.
- 짧은 초반 보드의 기록은 `twelve-guardians-rankings-v3`에 저장됩니다. 이전 v1/v2 기록과는 비교하지 않으며, 이전 키를 그대로 보존하고 이름만 이어받습니다. 이전 기록을 보는 UI는 아직 없습니다. 브라우저 데이터 삭제·앱 삭제로 사라질 수 있고, 계정 동기화/백업은 없습니다. 로컬 데이터이므로 변조 방지나 온라인 점수 검증을 제공하지 않습니다.

온라인 전체 순위로 확장할 때는 사용자 식별, 공통 배치/규칙 버전, 서버 측 이동 기록 검증, 보상 사용 검증, 저장 권한 및 닉네임 관리가 필요합니다. 현재 구현은 외부 서버에 이름이나 기록을 전송하지 않습니다.

## 난이도와 크기

입문만 처음부터 열리며, 각 단계를 클리어하면 바로 다음 단계가 열립니다. 여정·연습 모두 같은 단계 잠금을 적용하고 어느 모드든 정상 클리어하면 해제됩니다. 해제한 단계는 재도전할 수 있습니다. `twelve-guardians-progress-v1`에 완료한 연속 단계 수를 별도로 저장합니다. 이전 버전에서 높은 단계를 선택해 둔 것만으로는 클리어로 인정하지 않습니다. 저장 실패 시 이번 실행에서만 해제 상태를 유지하고 클리어 화면에 경고합니다.

| 단계     | 보드 (가로 열 × 세로 용량) | 동물 종류 | 숨김 깊이 상한 |
| -------- | -------------------------- | --------- | -------------- |
| 1 입문   | 6 × 4                      | 4종       | 0              |
| 2 산책   | 8 × 5                      | 6종       | 2              |
| 3 탐험   | 12 × 12                    | 10종      | 3              |
| 4 도전   | 14 × 16                    | 12종      | 4              |
| 5 수호왕 | 16 × 20                    | 14종      | 5              |

각 종류는 칸 용량만큼 존재하며, 총 빈 공간은 두 열 분량입니다. 역이동으로 섞으므로 시작 시 반드시 두 열이 비어 있는 것은 아닙니다. 맨 위 동물은 항상 공개됩니다. 보조 칸 사용 시 한 열이 추가됩니다. 5단계 이후는 같은 최대 크기로 새 배치가 나오며 무한히 커지지 않습니다. 작은 화면의 큰 보드는 좌우 스크롤로 탐색합니다.

고양이와 병아리를 손님 동물로 추가해 총 14종입니다. 두 동물은 첫 단계부터 등장하고, 12 수호동물은 순서대로 합류합니다. 14종 모두 같은 얼굴 중심 비율·선·색감의 `guardian-atlas-v3.png` 4×4 아틀라스를 사용합니다. 이전 전신 그림과 별도 고양이/병아리 아틀라스는 보존하지만 게임에서는 사용하지 않습니다.

같은 동물 묶음을 여러 개씩 역이동하며 섞어, 한 번 다른 동물을 올린 뒤 바로 섞기가 멈추던 현상을 줄였습니다. 시드마다 20개 후보를 만들어 열 내부의 종류 전환 횟수가 가장 많은 배치를 선택합니다. 모든 후보는 합법적인 복원 경로가 있습니다. 이는 구조적 혼합도 지표이며 최적 풀이 수나 사용자 성공률 기준의 난이도 보정은 아닙니다.

운보다 계획에 비중을 두도록 고난도에서도 맨 아래 3~5칸만 숨깁니다. 모두 공개 모드에서는 보드 전체를 보고 계획할 수 있습니다. 보드 높이를 축소하지 않고 페이지를 세로로 스크롤하며, 큰 보드의 가로 스크롤도 유지합니다.

원작 에셋을 복사하지 않았습니다. 14종은 내장 image_gen으로 만든 [전용 그림](./assets/guardian-atlas-v3.png)을 사용하며, 프롬프트와 수정 기록은 [에셋 기록](./assets/README.md)에 있습니다.

## 그림과 연출

- 맨 위 동물을 손가락/마우스로 끌어 놓는 드래그와 기존 두 번 터치를 함께 지원합니다. 드래그 중 목적지를 강조하고 화면 가장자리에서 가로·세로 자동 스크롤합니다. 맨 위 타일에서 시작한 제스처만 드래그로 잡으며 나머지 보드는 기본 스크롤을 유지합니다. 바깥·가득 찬 열·자기 열 드롭, pointercancel, 앱 전환은 차감 없이 취소합니다.
- 동일한 그림체의 4×4 투명 스프라이트 시트(14종 + 빈 셀 2개)로 기기별 이모지 차이 제거.
- 실제 출발/도착 좌표를 잇는 타일 이동, 물음표 앞뒤 뒤집기, 착지·열 완성·클리어 효과.
- 이동 중 중복 입력 방지. 상태는 애니메이션 전에 저장하므로 새로고침해도 이동은 보존됩니다.
- 선택·이동·공개·완성 효과음. 기본 무음이며 소리 설정은 브라우저에 저장합니다.
- 시스템의 동작 줄이기 설정에서는 이동·뒤집기·축하 애니메이션을 생략합니다.

## 실제 오픈소스 재사용 범위

[alliterhorst/decanta-water-sort](https://github.com/alliterhorst/decanta-water-sort)의 커밋 `4130d868bc5eeba65f5de8cf9aec3669c18c78cf`를 기준으로 다음 코드를 `engine.js`에 JavaScript로 이식했습니다.

- `src/core/engine.ts`: 상태 복사, 맨 위 색상, 단색/완성 판정, 이동 가능 판정, 불변 이동 적용, 가능한 이동 열거, 승리 판정.
- `src/core/generator.ts`: `mulberry32` 시드 난수 함수.
- 변경: 물 대신 펫, 한 타일씩 이동, 연금술/잠금/와일드카드 제거, 숨김 상태에 맞춘 판정.
- 신규 작성: 한국어 UI, 보드 렌더링, 공개 연출, 저장/복원 검증, 역이동 생성기와 테스트. 원본 전체 앱·렌더러·생성기·솔버를 가져온 것은 아닙니다.

원본 MIT 고지는 [LICENSE](./LICENSE)에 있습니다. 이전 `cow_and_cow` 기반 설명과 코드는 현재 정렬 버전에 사용하지 않습니다.

## 생성 및 테스트

완성된 보드에서 **정방향으로 되돌릴 수 있는 한 타일 역이동만** 적용하여 섞습니다. 생성기는 복원 경로도 반환하며, 테스트가 그 경로 전체를 실제 엔진으로 실행해 클리어를 검증합니다. 난이도는 최적 풀이 길이로 보정하지 않았습니다.
